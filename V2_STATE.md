## Architectural decisions

- Do not repair the existing WPF/client architecture.
- The Windows/WPF client is retired.
- The new desktop client is C++ with Qt 6, Qt Quick/QML, KDE Frameworks 6 and Kirigami.
- Breeze/KDE desktop styling supersedes the old Fluent-theme requirement.
- KI18n is the localization path; KConfig is the local client-settings path.
- Reuse business rules, domain knowledge, terminology and useful workflow ideas from the legacy code; do not mechanically port implementation structure.
- Build the new server/API as a small, explicit architecture rather than generated CRUD modules.
- Server target: .NET 10 LTS.
- Persistence target: LINQ to DB for typed SQL/query composition, FluentMigrator for migrations.
- Target databases: SQLite, PostgreSQL, SQL Server, MySQL/MariaDB.
- `Encounter` is the primary clinical event. Visit, Endoscopy, ClinicalExam and INFAI are encounter-specific records.
- Encounter extension tables use `EncounterId` as both PK and FK; they do not duplicate PatientId, AppointmentId, timestamps, urgency or a second identity.
- Appointments are planning records and may resolve into encounters; encounters may also be created without appointments.
- Appointment-to-Encounter is represented by a separate one-to-one link table instead of a nullable unique foreign key so the schema behaves consistently across supported databases.
- New v2 entity IDs use UUIDv7 generated by the server. The initial SQL representation is the canonical 36-character UUID string for provider portability.
- The one-active-non-INFAI-encounter rule is enforced transactionally by atomically claiming the singleton `practice_state.active_encounter_id` slot. INFAI does not claim the slot.
- The server must support daemon/service hosting and CLI administration.
- Configuration is external and portable; YAML is the intended human-facing format.
- Preserve UTC at persistence/API boundaries and localize only at the UI boundary.
- Avoid DTO-specific mapping frameworks when direct typed projections/commands are sufficient.
- Client accesses clinical data only through the API; never direct SQL.
